# Ask: backend ↔ frontend contract

Screens call the backend through **server actions**: the ask flow is in `src/server/actions/ask.ts`; asks, the board and every step after posting are in `board.ts`; private asks in `private.ts`; inbox and messages in `inbox.ts`; sign-in, profile and blocking in `session.ts` (all under `src/server/actions/`). Data lives in Postgres (see "Storage" at the end). Import a function and `await` it like any other async function, with no `fetch` and no URLs. All shared types live in `src/lib/ask/types.ts`, and seed data in `src/lib/ask/mock-data.ts`.

Status: **✅ exists** means you can call it today. **🟡 planned** means the signature below is the promise, and you can mock it until it lands (see "Mocking" at the end).

## Who can call what

The landing page is the public board. **Anyone can view it**: `listBoard` and `getCard` need no account. **Posting and taking an ask need the mocked sign-in**: `mockSignIn({ firstName, email })` with an `@dartmouth.edu` email (the `/signin` page's mocked "Sign in with Dartmouth" step), no verification. It sets a session cookie on that browser. An asker step (confirm, done, pay, thanks, share) works only for the person who posted the card. Every one of these is checked on the server.

- Signed out → `{ error: "Sign in to post or help." }`. Show the sign-in form (first name + school email), then retry.
- `getMe()` → `{ firstName, email } | null` tells you who's signed in on this browser; `mockSignOut()` clears it. All three are in `src/server/actions/session.ts`.
- `PublicCard.viewer` is `"asker"`, `"helper"`, `"invited"` (picked for a private ask), `"other"` or `"signed-out"`. Use it to pick the buttons: the asker sees Confirm / Pay to hold / Confirm done / Report a problem / Share, the helper sees Done, a signed-in `"other"` sees "I can help" on an open card, and `"signed-out"` sees "Sign in to help".

## Design screens → actions

Source: the "Ask: design and contract map" doc and the [design canvas](https://claude.ai/artifact/SHnbdWVPwMQmpdgPy2kwqE). Statuses below come from the code on `dev`, not the doc (the doc lists some board actions as planned; they exist in `board.ts`).

How the flows connect:

- **Asker:** Needs board → Post a need → Quick check (`checkSafety`) routes it. `none` → Where it goes (board, Share to GroupMe or Ask privately, plus expiry) → Waiting. `sensitive` → Kept private (board and GroupMe locked) → Ask privately → Waiting. `crisis` / `academic` → Support resources, never posted or matched. `blocked` (planned) → Quick check: can't post. Then Waiting → Confirm helper → Claimed task → Pay (mock) → Thank you. No yes in time → Ask expired → Post again.
- **Helper:** Needs board → Task detail → Claim → Payouts (mock).
- **Everywhere:** bottom bar with Feed, Claimed, Ask, Inbox, Me. Claimed lists my asks and what I'm helping with. Inbox has All, Actions (needs a tap) and Updates (info only).

## Rules every screen follows

- Nothing is sent, posted, paid or added to a calendar without an explicit tap. Disable the button while its action is in flight.
- Every action that can fail returns `{ error: string }`. Show that string as-is; it's written for the user.
- Hide group sharing and the board unless the safety category is `"none"`. The server rejects it anyway.
- Anonymous posts: show `ScrubResult.removed` with an Undo.
- On "I can help", the server decides who wins. A loser gets `{ error: "Already taken" }`, so refresh the card.
- Never show a helper's email. `PublicCard` doesn't contain it. A helper's school email is shared only after both sides say yes.
- Free favors (`price: 0`) skip the Pay screen. Paid asks: the asker pays to hold right after confirming; the helper can't tap Done until it's held.
- Show `autoConfirmAt` on the asker's Claimed task ("Confirms automatically on Sat 3 pm") next to "Confirm done" and "Report a problem".
- Every card shows when it expires. After that it leaves the board, and the GroupMe link shows "This ask has expired".
- Inbox Actions always need a tap; Updates never do. All shows both.
- A blocked ask is never posted, shared or matched. Show the reason and offer a suggested rewrite (checked again on tap), tutoring, or discard.
- No ratings, stars or scores anywhere. The asker writes a thank-you note.

## Key types (`src/lib/ask/types.ts`)

- `BoardCard` / `PublicCard`: one ask, one card, with `title`, `text` ("what done looks like"), `category` (free text, max 24 chars: a preset from `src/lib/ask/categories.ts` matching the Who to ask interests such as Rides / Moving stuff / US paperwork; the first interest picked on Post a need, or what the asker typed under Other; default `Other`), `payType` (pay / fund / trade / free), `private`, `startsAt?`, `neededBy?`, `askerYear?`, `shares: { groupId, postedAt }[]`, and `payment?` (asker and helper only). `PublicCard` never has user ids or the helper's email, and hides the asker's name on anonymous cards; it adds `viewer` and `heldByFirstName`. `status`: `open → held → confirmed → done` (or `expired` / `cancelled`). `price` is whole dollars, where `0` means a favor. `minutes` is how long the help takes. `expiresAt` is in ms.
- `Helper`: `interests`, seeded weekly `busy` slots (free/busy only), `weeklyLimit`, `canAcceptPayment`.
- `Result<T>`: `({ ok: true } & T) | { error: string }`.

## Decided (Oct 30, design vs PRD)

- **Payment (revised Oct 30, late):** hold, then release. The asker taps "Pay $X and hold" right after confirming the helper (`payToHold`). The helper taps Done (`markHelperDone`); the asker confirms (`markDone`) to release it, or it auto-releases 48 h after the helper's Done unless the asker reports a problem (`reportProblem`). Cancelling before the helper's Done refunds it. Replaces the earlier "pay after done" note, which left helpers unpaid if the asker never tapped Pay. All mocked; no money moves.
- **No ratings:** the design's "Rate your helper" screen is the thank-you note (`saveCardThanks`), with no stars or score.
- **Posting path:** the board flow is `postToBoard` (explicit tap) → optional `shareCardToGroup` (explicit tap). `postAsk` / `claimAsk` in `ask.ts` are the old group-first flow (in-memory); don't use them for new screens.
- **Emails:** `notify()` in `src/lib/notify/` (console only tonight, `[mock:email]` in the server log). Sent after the winning update for exactly three events: a private ask reaches a helper (`sendPrivately`), someone says "I can help" (`claimCard`, `respondToRequest`), and the other side marks done (`markHelperDone` → asker, `markDone` → helper). Skipped when the user turned email notifications off; never names the asker. Nothing for the screens to call.
- **Bot intro:** `pnpm bot:intro <groupId>` posts "I post asks from Ask. I can't read your messages. Remove me anytime." once, by hand, when the bot joins a group. Never sent with regular posts.
- **Sign-in:** mocked for now (`mockSignIn` behind a mocked "Sign in with Dartmouth" button: first name + `@dartmouth.edu` email only, no codes). The design's phone + two-code Verify screen is not built (TODO(auth)).

## Storage

All of this is in Postgres (tables in `src/db/schema/ask.ts`, migration `drizzle/0002_ask_tables.sql`). Locally it's an in-process PGlite database, migrated and seeded on first use and reset on restart. With `ASK_DB=postgres` it's the shared Supabase database, so two phones (and every Vercel instance) see the same card; run `pnpm db:migrate` first.

## Open decisions

- Suggested price (decided for tonight, `src/lib/ask/price.ts`; the model never sets it): rides and moving ~$20/hr (floor $10), everything else ~$15/hr (floor $5), rounded to $5, range ±$5; 10 min or less suggests $0 (favor). 45-min ride → $15 ($10–20).
- Who to ask (`src/lib/ask/helper-fit.ts`): `HelperPrefs.needs` must be seeded helper tags; `fits`/`fitsPaid` are a preview count only. `matchHelpers` adds free/busy, weekly limits and load spreading.
